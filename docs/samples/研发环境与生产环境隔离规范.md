## 1. 目的与范围

本规范旨在明确研发环境（Development Environment）与生产环境（Production Environment）之间的隔离策略，防止因环境混用导致的数据泄露、服务中断或配置错误。适用于公司所有业务系统、中间件、数据库及基础设施。

## 2. 网络隔离要求

### 2.1 VPC 与子网规划

所有环境必须部署在独立的 VPC 中，禁止跨 VPC 直接路由。

| 环境 | VPC CIDR | 子网类型 | 示例子网段 |
|------|----------|----------|------------|
| 生产环境 | 10.0.0.0/16 | 公有子网 | 10.0.1.0/24 |
| | | 私有子网 | 10.0.2.0/24 |
| 预发布环境 | 10.1.0.0/16 | 私有子网 | 10.1.1.0/24 |
| 测试环境 | 10.2.0.0/16 | 私有子网 | 10.2.1.0/24 |
| 研发环境 | 10.3.0.0/16 | 私有子网 | 10.3.1.0/24 |

### 2.2 防火墙与安全组规则

生产环境安全组仅允许来自公司负载均衡器（ALB/NLB）及堡垒机（Bastion Host）的流量。所有研发环境与生产环境之间的通信必须经过 API Gateway 和 VPN 隧道。

```
# 生产环境安全组示例（仅允许必要端口）
- 入站规则：
  - 协议: TCP, 端口: 443, 源: 10.0.0.0/16 (内部ALB)
  - 协议: TCP, 端口: 22, 源: 192.168.1.0/24 (堡垒机)
- 出站规则：
  - 协议: ALL, 目标: 0.0.0.0/0 (仅限特定服务)
```

## 3. 账号与权限隔离

### 3.1 云平台 IAM 策略

每个环境使用独立的 AWS Account 或阿里云 RAM 账号。生产环境账号必须启用 MFA 和审计日志。

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Deny",
      "Action": "*",
      "Resource": "*",
      "Condition": {
        "BoolIfExists": {
          "aws:MultiFactorAuthPresent": "false"
        }
      }
    }
  ]
}
```

### 3.2 数据库访问控制

- 生产数据库：仅允许通过白名单 IP 访问，白名单包含堡垒机 IP 和监控系统 IP。
- 研发数据库：允许开发人员通过 VPN 访问，但禁止直连生产数据库。

```sql
-- 生产数据库白名单示例（MySQL）
CREATE USER 'app_user'@'10.0.2.5' IDENTIFIED BY 'prod_password';
GRANT SELECT, INSERT, UPDATE, DELETE ON prod_db.* TO 'app_user'@'10.0.2.5';
FLUSH PRIVILEGES;
```

## 4. 数据与配置隔离

### 4.1 数据库数据隔离

生产环境数据严禁导入研发环境。如需测试数据，必须使用脱敏工具（如 `mysqldump --where` 或 `DataMask`）生成模拟数据集。

```
# 数据脱敏导出示例
mysqldump -h prod-db.example.com -u dba -p --where="created_at < '2024-01-01'" prod_db > prod_backup.sql
python3 mask_data.py --input prod_backup.sql --output dev_data.sql
```

### 4.2 配置管理

使用 ConfigMap（Kubernetes）或 AWS Parameter Store 管理环境差异配置。生产环境密钥必须加密存储，研发环境使用模拟密钥。

```yaml
# Kubernetes ConfigMap 示例（研发环境）
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  namespace: dev
data:
  DB_HOST: "dev-db.internal"
  DB_PORT: "3306"
  LOG_LEVEL: "DEBUG"
---
# 生产环境使用 Secret 存储敏感配置
apiVersion: v1
kind: Secret
metadata:
  name: app-secret
  namespace: prod
type: Opaque
data:
  DB_PASSWORD: <base64-encrypted-password>
```

## 5. 容器化环境隔离

### 5.1 Kubernetes 命名空间

所有环境使用独立的 Kubernetes 集群或命名空间（Namespace）。生产集群必须启用 Pod Security Policy 和网络策略（NetworkPolicy）。

```yaml
# 网络策略示例：仅允许来自 ingress-nginx 的流量
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all-except-ingress
  namespace: prod
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          name: ingress-nginx
    ports:
    - protocol: TCP
      port: 8080
```

### 5.2 镜像仓库隔离

- 生产镜像：存储于 `registry.prod.company.com`，必须经过安全扫描和签名。
- 研发镜像：存储于 `registry.dev.company.com`，允许开发人员推送未签名的镜像。

## 6. 日志与监控隔离

- 生产环境日志：集中存储于 ELK 集群（`logs.prod.company.com`），保留 180 天。
- 研发环境日志：存储于独立 ES 实例，保留 30 天。
- 监控告警：生产环境告警发送至 PagerDuty，研发环境告警仅发送至钉钉群。

## 7. 违规处理

任何违反本规范的行为，包括但不限于：
- 将生产数据库密码硬编码在代码仓库中
- 通过研发环境直连生产数据库
- 将生产数据导入非脱敏的研发环境

将根据《信息安全管理制度》进行通报批评，情节严重者暂停环境访问权限。
