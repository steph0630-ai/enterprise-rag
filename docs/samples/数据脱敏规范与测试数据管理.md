## 2. 目的与适用范围

### 2.1 目的

规范企业内敏感数据的脱敏处理流程与测试数据管理机制，确保在生产环境、测试环境、开发环境及第三方协作过程中，敏感信息受到有效保护，避免数据泄露风险。

### 2.2 适用范围

本规范适用于所有涉及个人身份信息（PII）、财务数据、用户认证信息的企业内部系统及外部合作项目。

## 3. 数据分类与脱敏规则

### 3.1 敏感数据分类

| 类别代码 | 数据类别             | 示例字段                     | 脱敏要求 |
|----------|----------------------|------------------------------|----------|
| S1       | 个人身份标识         | 姓名、身份证号、护照号       | 强制脱敏 |
| S2       | 联系方式             | 手机号、邮箱、家庭地址       | 强制脱敏 |
| S3       | 金融账户信息         | 银行卡号、交易流水、余额     | 强制脱敏 |
| S4       | 认证凭据             | 密码、Token、Private Key     | 不可明文存储 |
| S5       | 业务敏感数据         | 合同金额、客户评级           | 按需脱敏 |

### 3.2 标准脱敏规则

| 字段类型     | 脱敏方法                          | 示例（原始 → 脱敏后）                    |
|--------------|-----------------------------------|------------------------------------------|
| 姓名         | 保留姓氏，其余用`*`替代          | 张三 → 张*                              |
| 身份证号     | 前6位保留，后4位保留，中间用`*`   | 110101199001011234 → 110101********1234 |
| 手机号       | 前3位+后4位保留，中间用`*`        | 13800138000 → 138****8000               |
| 邮箱         | 用户名部分用`***`替代，域名保留   | user@company.com → ***@company.com      |
| 银行卡号     | 前6位保留，后4位保留，中间用`*`   | 6222021234567890 → 622202******7890     |
| 地址         | 保留省市区，详细地址用`*`替代     | 北京市朝阳区建国路88号 → 北京市朝阳区*** |
| 密码/Token   | 不允许明文存储，使用SHA-256哈希   | myPassword123 → e10adc3949ba59abbe56e...|

### 3.3 动态脱敏配置示例（基于 DataMask v4.0）

```yaml
# 动态脱敏策略配置 - dm_policy_prod.yaml
version: "4.0"
rules:
  - field_path: "user.phone"
    mask_type: "partial_keep"
    keep_front: 3
    keep_back: 4
    replace_char: "*"
  - field_path: "transaction.card_number"
    mask_type: "partial_keep"
    keep_front: 6
    keep_back: 4
    replace_char: "*"
  - field_path: "user.email"
    mask_type: "regex_replace"
    pattern: "^(.+)@"
    replacement: "***@"
```

## 4. 测试数据管理流程

### 4.1 测试数据生命周期

```
数据申请 → 脱敏处理 → 加载至测试环境 → 使用与监控 → 数据回收
```

### 4.2 测试数据申请与审批

所有测试数据申请必须通过统一工单平台（Jira DataReq）发起，填写以下内容：

- 申请项目名称与编号
- 所需字段列表
- 数据量级（行数/记录数）
- 使用期限（最长不超过45天）
- 负责人及备份邮箱

审批路径：数据安全组（1个工作日） → 对应业务部门负责人（1个工作日）

### 4.3 脱敏执行命令示例（使用 datamask-cli）

```bash
# 对生产数据库 user 表执行静态脱敏，输出至测试环境
datamask-cli \
  --source mysql://prod-host:3306/erp_db \
  --target mysql://test-host:3306/test_erp \
  --config dm_policy_prod.yaml \
  --tables user,transaction,account \
  --batch-size 10000 \
  --threads 8 \
  --log-level info \
  --dry-run false
```

### 4.4 脱敏验证脚本

```python
# validate_masking.py
import re

def check_phone_masked(phone: str) -> bool:
    """验证手机号是否已脱敏：138****8000 格式"""
    pattern = r'^\d{3}\*{4}\d{4}$'
    return bool(re.match(pattern, phone))

def check_id_card_masked(id_card: str) -> bool:
    """验证身份证号脱敏：前6位+****+后4位"""
    pattern = r'^\d{6}\*{8}\d{4}$'
    return bool(re.match(pattern, id_card))

# 批量验证示例
test_records = [
    {"phone": "138****8000", "id_card": "110101********1234"},
    {"phone": "13812348000", "id_card": "110101199001011234"},
]

for record in test_records:
    assert check_phone_masked(record["phone"]), f"Phone masking failed: {record['phone']}"
    assert check_id_card_masked(record["id_card"]), f"ID card masking failed: {record['id_card']}"
```

## 5. 数据回收与审计

### 5.1 回收机制

- 测试环境数据使用到期后，由自动化脚本（`data_cleanup.py`）执行全量删除
- 删除操作记录日志至 `s3://audit-logs/data-reclamation/`
- 回收确认邮件发送至数据安全组和申请负责人

### 5.2 审计日志要求

| 字段             | 类型     | 说明                     |
|------------------|----------|--------------------------|
| timestamp        | datetime | 操作时间                 |
| operator         | string   | 操作人 UID               |
| action_type      | enum     | EXPORT / MASK / LOAD / DELETE |
| source_db        | string   | 源数据库连接标识         |
| target_db        | string   | 目标数据库连接标识       |
| records_count    | int      | 涉及记录数               |
| mask_policy_hash | string   | 脱敏策略的 SHA256 哈希值 |
| status           | enum     | SUCCESS / FAILED         |

## 6. 违规处理与合规附录

### 6.1 违规处理

- 未按规定进行脱敏即导出测试数据，视为 **严重违规**，记入安全违规档案
- 首次违规：责任人书面检讨 + 数据安全培训（4学时）
- 二次违规：责任人绩效扣减5% + 项目数据访问权限暂停2周
- 造成实际数据泄露的：按《数据安全事件应急响应流程》处理

### 6.2 合规参考

- 《个人信息保护法》第21条：委托处理个人信息的，应当约定数据脱敏义务
- 《金融数据安全分级指南》JR/T 0197-2020：三级及以上数据须采用不可逆脱敏
- ISO 27701:2019 隐私信息管理体系：测试数据不得包含真实PII
