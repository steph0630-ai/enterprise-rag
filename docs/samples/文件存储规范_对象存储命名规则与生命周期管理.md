## 1. 概述

本规范定义企业内部对象存储（Object Storage）的命名规则与生命周期管理策略。自生效之日起，所有新建 Bucket 及数据写入必须遵循本规范，已有存量数据需在 30 天内完成迁移或整改。未遵循规范的 Bucket 将被系统自动冻结写入权限。

## 2. 命名规则

### 2.1 Bucket 命名规则

Bucket 名称必须符合以下约束：

- **全局唯一**：与企业内部 DNS 域名一致，采用 `<team>-<project>-<env>-<region>` 模式
- **字符限制**：仅允许小写字母、数字和连字符（`-`）
- **长度限制**：3-63 个字符
- **禁止前缀**：禁止使用 `log-`、`backup-` 作为 Bucket 前缀，改用 `data-` 或 `asset-`

**示例：**

| 合法名称                        | 非法名称                     | 原因           |
|---------------------------------|------------------------------|----------------|
| `data-payment-prod-cn-beijing`  | `payment-prod`               | 缺少团队前缀   |
| `asset-user-avatar-dev-us-east` | `user-avatar-Dev-East`       | 包含大写字母   |
| `log-payment-prod-cn-shanghai`  | `log-payment-prod-cn-shanghai` | 禁止使用 `log-` 前缀，改为 `data-payment-prod-cn-shanghai` |

### 2.2 对象键（Object Key）命名规则

对象键即文件路径，必须遵守以下层级结构：

```
<type>/<business>/<env>/<date>/<filename>.<ext>
```

- `type`：固定为 `raw`（原始数据）、`processed`（处理数据）、`archive`（归档数据）、`temp`（临时数据）
- `business`：业务名称，如 `order`、`user`、`payment`
- `env`：环境标识，`prod`、`staging`、`dev`、`test`
- `date`：日期格式 `YYYY/MM/DD` 或 `YYYY-MM-DD`，推荐使用 `/` 分隔以优化 List 性能
- `filename`：文件名，仅允许字母、数字、下划线、连字符，禁止空格与特殊字符
- `ext`：文件扩展名，全小写

**示例：**

```
raw/order/prod/2024/09/10/order_20240910_001.csv
processed/user/staging/2024-09-10/user_profile_v2.json
archive/payment/dev/2024/08/01/payment_report_20240801.pdf
temp/upload/test/2024/09/11/tmp_abc123.jpg
```

**注意事项：**

- 禁止在对象键中使用 `..` 或 `//` 等可能引起路径解析歧义的字符
- 文件名内容中禁止包含敏感信息（如身份证号、手机号），需进行脱敏处理（例如 `user_****1234.csv`）

## 3. 生命周期管理策略

### 3.1 存储层级定义

| 层级       | 存储类型        | 适用场景                   | 最低保留时间 | 访问频率       |
|------------|-----------------|----------------------------|--------------|----------------|
| 热存储     | Standard        | 实时读取、频繁修改的文件     | 无           | > 1 次/周      |
| 温存储     | Infrequent Access | 月报、周报、历史日志       | 30 天        | 1 次/月        |
| 冷存储     | Archive         | 审计日志、备份文件           | 90 天        | < 1 次/季度    |
| 深度归档   | Deep Archive    | 合规保留、法律证据文件       | 180 天       | 极少访问       |

### 3.2 生命周期规则示例

以下为针对 `data-payment-prod-cn-beijing` Bucket 的完整生命周期策略（S3 语法）：

```json
{
  "Rules": [
    {
      "Id": "move-to-ia-after-30days",
      "Status": "Enabled",
      "Filter": {
        "Prefix": "raw/order/prod/"
      },
      "Transitions": [
        {
          "Days": 30,
          "StorageClass": "STANDARD_IA"
        }
      ]
    },
    {
      "Id": "move-to-glacier-after-90days",
      "Status": "Enabled",
      "Filter": {
        "Prefix": "processed/payment/prod/"
      },
      "Transitions": [
        {
          "Days": 90,
          "StorageClass": "GLACIER"
        }
      ],
      "Expiration": {
        "Days": 365,
        "ExpiredObjectDeleteMarker": true
      }
    },
    {
      "Id": "delete-temp-after-7days",
      "Status": "Enabled",
      "Filter": {
        "Prefix": "temp/"
      },
      "Expiration": {
        "Days": 7
      }
    }
  ]
}
```

### 3.3 生命周期配置建议

- **temp 目录**：所有以 `temp/` 开头的对象，应在 7 天内自动删除。若需要临时存储超过 7 天，需在对象元数据中添加 `x-amz-tagging: retain=true` 标记，并额外申请审批。
- **raw 目录**：原始数据保留至少 90 天，之后转入温存储（Infrequent Access）。若数据为日志文件，保留 180 天后进入冷存储。
- **archive 目录**：归档数据直接写入冷存储，保留 365 天后自动过期删除。需要长期保留的，使用合规保留策略（Legal Hold）或对象锁定（Object Lock）。
- **对象标签**：所有 Bucket 必须启用对象标签，至少包含 `team`、`project`、`env` 三个标签。示例：

```bash
aws s3api put-bucket-tagging --bucket data-payment-prod-cn-beijing --tagging 'TagSet=[{Key=team,Value=payment},{Key=project,Value=order},{Key=env,Value=prod}]'
```

## 4. 异常处理流程

### 4.1 命名违规处理

- 系统每周扫描一次所有 Bucket 名称与对象键，生成违规报告发送至团队负责人邮箱
- 违规 Bucket 在 7 天内未整改的，自动标记为 `READ_ONLY` 状态；14 天后仍未整改的，自动冻结写入权限
- 违规对象键所在 Bucket 将被限制 List 操作，仅允许通过指定前缀进行访问

### 4.2 生命周期规则冲突

当多个生命周期规则作用于同一对象时，遵循以下优先级：

1. 对象的 `x-amz-tagging` 标签（显式指定保留策略）
2. 对象所在 Bucket 的默认生命周期规则
3. 团队自定义的生命周期策略（通过 CMDB 配置）

冲突发生时的处理步骤：

```bash
# 步骤1：检查对象的标签
aws s3api get-object-tagging --bucket data-payment-prod-cn-beijing --key raw/order/prod/2024/09/10/order_20240910_001.csv

# 步骤2：若标签未指定保留策略，查看 Bucket 生命周期
aws s3api get-bucket-lifecycle-configuration --bucket data-payment-prod-cn-beijing

# 步骤3：若仍无法确定，联系基础设施团队（infra@company.com）
```

## 5. 合规与审计

- 所有 Bucket 必须启用访问日志（Server Access Logging），日志写入专用审计 Bucket `audit-log-<region>`
- 生命周期规则变更需经过变更评审（Change Advisory Board, CAB）审批
- 每季度进行一次存储成本审计，评估生命周期策略的执行效率
