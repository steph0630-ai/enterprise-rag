## 1. 背景与目标

当前业务系统中，订单、库存、支付三个核心微服务通过独立数据库部署，跨服务的数据一致性依赖 TCC 模式。随着业务量增长（日均订单 50 万+），TCC 模式暴露出以下问题：

- **Try 阶段超时**：库存预扣接口 RT 在高峰期达 800ms+，导致全局事务回滚率上升至 3.2%
- **Confirm 幂等性不足**：部分场景下因网络重试导致库存重复扣减
- **开发成本高**：每个业务方需手动实现 try/confirm/cancel 三个接口，人均开发周期增加 2 天

本次选型目标：在保证数据最终一致性的前提下，降低开发复杂度，提升系统吞吐量。核心约束：
- 不允许使用强一致性方案（如 XA），避免长事务锁表
- 必须支持 MySQL 与 Redis 混合存储场景（例如库存预扣后写入 Redis 缓存）
- 最大容忍不一致时长：10 秒

## 2. 候选方案对比

| 方案             | 一致性模型 | 隔离级别     | 框架/实现         | 开发复杂度 | 运维成本 | 适用场景                 |
| ---------------- | ---------- | ------------ | ----------------- | ---------- | -------- | ------------------------ |
| TCC              | 最终一致   | 自定义       | 自研 + Seata TCC  | 高         | 中       | 短事务、高一致性要求     |
| Saga             | 最终一致   | 无隔离       | Seata Saga / 自研 | 中         | 中       | 长事务、允许补偿         |
| 消息最终一致性   | 最终一致   | 无隔离       | RocketMQ 事务消息 | 低         | 低       | 异步、非关键路径         |
| **RocketMQ 事务消息 + 本地消息表** | 最终一致 | 读已提交（业务层） | 自研封装 | **低**     | **低**   | 异步、高峰值、混合存储   |

**选型结论**：优先采用 **RocketMQ 事务消息 + 本地消息表** 方案，作为订单系统与库存系统的数据一致性保障。对于支付场景（需严格时序），保留 TCC 作为备用方案。

## 3. 方案详细设计

### 3.1 整体架构

```
[订单服务] --(半消息)--> [RocketMQ] --(commit)--> [库存服务]
    |                        |                        |
    |--(本地消息表)-----> [定时任务] --(重试)--> [库存服务]
```

流程说明：
1. 订单服务在本地事务中写入订单表，同时将一条消息插入本地消息表（状态：pending）
2. 订单服务发送 RocketMQ 半消息（half message），此时消息对消费者不可见
3. 订单服务本地事务提交后，执行 `sendMessageInTransaction` 的 `commit` 回调，将半消息转为正式消息
4. 库存服务消费消息，执行库存扣减操作
5. 若第 3 步失败（本地事务提交但 commit 未执行），RocketMQ 会回查订单服务的本地消息表，根据状态决定 commit 或 rollback
6. 若库存服务消费失败，通过本地消息表定时任务进行重试（最多 5 次，间隔 5s/10s/30s/60s/120s）

### 3.2 关键配置

#### RocketMQ 事务消息配置

```yaml
# application.yml
rocketmq:
  name-server: 192.168.1.100:9876;192.168.1.101:9876
  producer:
    group: order-tx-producer
    send-message-timeout: 3000
    retry-times-when-send-failed: 2

    group: stock-tx-consumer
    consume-thread-min: 20
    consume-thread-max: 64
    consume-timeout: 15000
```

#### 本地消息表 DDL

```sql
CREATE TABLE `local_message` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT,
  `business_key` varchar(64) NOT NULL COMMENT '业务主键（如订单号）',
  `message_body` text NOT NULL COMMENT '消息内容（JSON格式）',
  `status` tinyint(4) NOT NULL DEFAULT '0' COMMENT '0:待发送 1:已发送 2:已消费 3:已回滚',
  `retry_count` int(11) NOT NULL DEFAULT '0' COMMENT '重试次数',
  `next_retry_time` datetime DEFAULT NULL COMMENT '下次重试时间',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_business_key` (`business_key`),
  KEY `idx_status_next_retry` (`status`,`next_retry_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 3.3 核心代码示例

#### 订单服务：发送事务消息

```java
@Component
public class OrderService {

    @Autowired
    private RocketMQTemplate rocketMQTemplate;
    @Autowired
    private LocalMessageMapper localMessageMapper;

    @Transactional(rollbackFor = Exception.class)
    public void createOrder(OrderCreateRequest request) {
        // 1. 写订单表
        orderMapper.insert(buildOrder(request));
        
        // 2. 写本地消息表
        LocalMessage msg = new LocalMessage();
        msg.setBusinessKey(request.getOrderId());
        msg.setMessageBody(JSON.toJSONString(buildStockDeductionMsg(request)));
        msg.setStatus(0);
        localMessageMapper.insert(msg);
        
        // 3. 发送半消息（事务消息）
        rocketMQTemplate.sendMessageInTransaction(
            "stock-deduction-topic",
            MessageBuilder.withPayload(msg.getMessageBody())
                .setHeader("business_key", msg.getBusinessKey())
                .build(),
            msg
        );
    }
}
```

#### RocketMQ 事务监听器

```java
@Component
@RocketMQTransactionListener(rocketMQTemplateBeanName = "rocketMQTemplate")
public class OrderTransactionListener implements RocketMQLocalTransactionListener {

    @Autowired
    private LocalMessageMapper localMessageMapper;

    @Override
    public RocketMQLocalTransactionState executeLocalTransaction(Message msg, Object arg) {
        // 本地事务已在 createOrder 方法中提交，此处直接返回 COMMIT
        // 若执行到此方法说明半消息已发送，但本地事务尚未提交
        // 实际通过 @Transactional 保证，此处返回 UNKNOWN 让 RocketMQ 回查
        return RocketMQLocalTransactionState.UNKNOWN;
    }

    @Override
    public RocketMQLocalTransactionState checkLocalTransaction(Message msg) {
        String businessKey = (String) msg.getHeaders().get("business_key");
        LocalMessage localMsg = localMessageMapper.selectByBusinessKey(businessKey);
        if (localMsg == null) {
            return RocketMQLocalTransactionState.ROLLBACK;
        }
        if (localMsg.getStatus() == 0 || localMsg.getStatus() == 1) {
            return RocketMQLocalTransactionState.COMMIT;
        }
        return RocketMQLocalTransactionState.ROLLBACK;
    }
}
```

#### 库存服务：消费消息

```java
@Component
@RocketMQMessageListener(
    consumerGroup = "stock-tx-consumer",
    topic = "stock-deduction-topic",
    consumeMode = ConsumeMode.ORDERLY
)
public class StockConsumer implements RocketMQListener<String> {

    @Autowired
    private StockService stockService;

    @Override
    public void onMessage(String message) {
        StockDeductionMsg msg = JSON.parseObject(message, StockDeductionMsg.class);
        // 幂等性检查：通过业务主键去重
        if (stockService.isDeductionDone(msg.getOrderId())) {
            return;
        }
        stockService.deductStock(msg.getSkuId(), msg.getQuantity());
    }
}
```
