## 2. 概述

本方案定义了用户行为数据的标准化采集、传输、存储与分析链路，覆盖Web端（H5/PC）、移动端（Android/iOS）及小程序。通过统一的埋点SDK，实现全端行为数据的一致性，支持业务方进行用户画像构建、漏斗分析、路径洞察及AB实验评估。

## 3. 埋点事件模型

所有埋点事件遵循统一的事件结构，采用JSON格式序列化。

### 3.1 基础事件结构

```json
{
  "event_id": "click_home_banner",      // 事件标识符，全局唯一
  "timestamp": 1723714560000,            // 事件发生时间戳（毫秒）
  "user_id": "u_abc123xyz",             // 用户唯一标识（登录态）
  "device_id": "d_android_8a3f7b2c",    // 设备唯一标识（匿名）
  "session_id": "s_20240815_a1b2c3d4",  // 会话ID
  "platform": "android",                // 平台: web | ios | android | miniapp
  "app_version": "4.2.1",               // 应用版本号
  "properties": {}                      // 事件自定义属性
}
```

### 3.2 通用属性说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| event_id | string | 是 | 命名规范：`<行为类型>_<模块>_<元素>`，如 `click_search_bar` |
| timestamp | long | 是 | 客户端本地时间，服务端会进行时钟校准 |
| user_id | string | 否 | 未登录时传空字符串 |
| device_id | string | 是 | 通过SDK生成的UUID，跨应用唯一 |
| session_id | string | 是 | 每次启动生成，后台运行超时30分钟则重建 |
| platform | string | 是 | 枚举值：web/ios/android/miniapp |
| app_version | string | 是 | 从打包配置读取，如 `4.2.1` |
| properties | object | 是 | 至少包含空对象 `{}`，不得为null |

## 4. 事件类型定义

### 4.1 核心事件类型

| 事件类型 | event_id 前缀 | 触发条件 | 必填属性 |
|----------|---------------|----------|----------|
| 页面浏览 | page_view_ | 页面加载完成或切换 | page_name, page_url, referrer |
| 元素点击 | click_ | 用户点击可交互元素 | element_name, position_x, position_y |
| 表单提交 | submit_ | 表单提交成功 | form_id, success_flag |
| 搜索行为 | search_ | 用户执行搜索 | keyword, result_count |
| 视频播放 | video_play_ | 视频开始播放 | video_id, duration |
| 错误上报 | error_ | 客户端捕获异常 | error_code, error_message |

### 4.2 自定义事件属性规范

以 `click_home_banner` 为例，properties 字段包含：

```json
{
  "banner_id": "banner_202408_01",
  "banner_position": 3,
  "campaign_id": "campaign_summer_2024",
  "is_logged_in": true,
  "network_type": "wifi"
}
```

## 5. 数据链路架构

行为数据从客户端产生到最终入库，经过以下链路：

```
客户端 SDK → 网关 (Nginx) → Kafka (实时流) → Flink (清洗/聚合) → HBase (存储)
                                                      ↓
                                               ClickHouse (OLAP)
```

### 5.1 客户端上报

- **上报协议**：HTTPS POST，Content-Type: `application/json`
- **批量策略**：每5秒或缓存满100条触发上报
- **重试机制**：失败后重试3次，间隔2s/5s/10s，超时丢弃
- **离线缓存**：本地SQLite缓存最多500条事件，应用启动时补发

### 5.2 服务端接收

```yaml
# Nginx 配置片段（/etc/nginx/conf.d/tracking.conf）
upstream tracking_backend {
    server 10.0.1.10:8080 weight=5;
    server 10.0.1.11:8080 weight=5;
    keepalive 32;
}

server {
    listen 443 ssl;
    server_name tracking.example.com;

    location /v2/event {
        proxy_pass http://tracking_backend;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 5s;
    }
}
```

### 5.3 Kafka 主题配置

| 主题名 | 分区数 | 副本数 | 保留策略 | 用途 |
|--------|--------|--------|----------|------|
| tracking.raw.events | 12 | 3 | 7天 | 原始事件流 |
| tracking.aggregated.events | 6 | 3 | 30天 | Flink聚合后数据 |
| tracking.error.dead.letter | 3 | 2 | 14天 | 解析失败的事件 |

## 6. 埋点接入规范

### 6.1 SDK 集成

#### Android (Gradle)

```gradle
dependencies {
    implementation 'com.example.tracking:tracking-sdk:2.3.1'
}
```

#### iOS (CocoaPods)

```ruby
pod 'TrackingSDK', '~> 2.3.1'
```

#### 手动初始化

```javascript
// Web端初始化示例
import TrackingSDK from '@example/tracking-sdk';

const tracker = new TrackingSDK({
  appId: 'com.example.app',
  endpoint: 'https://tracking.example.com/v2/event',
  autoTrack: ['page_view', 'click'],
  debug: false
});

tracker.initialize();
```

### 6.2 自定义埋点示例

```java
// Android 代码埋点
TrackingEvent event = new TrackingEvent.Builder("click_checkout_button")
    .addProperty("product_id", "prod_789")
    .addProperty("price", 299.00)
    .addProperty("currency", "CNY")
    .build();

TrackingSDK.getInstance().track(event);
```

## 7. 数据质量校验

### 7.1 服务端校验规则

| 校验项 | 规则 | 处理策略 |
|--------|------|----------|
| event_id 格式 | 必须匹配 `^[a-z_]+$` | 不合法则写入死信队列 |
| timestamp 范围 | 距离当前时间不超过1小时 | 超时事件丢弃 |
| user_id 黑名单 | 检查是否在刷量ID列表 | 命中则降级采样率至1% |
| 必填字段完整性 | 检查是否存在null或空对象 | 缺失则补默认值并标记 |

### 7.2 实时监控指标

- **事件接收QPS**：正常范围 8000-15000
- **解析成功率**：> 99.5%
- **端到端延迟**：P99 < 3秒
- **死信队列积压**：< 1000条

## 8. 隐私与合规

- 所有事件不得包含明文手机号、身份证、精确GPS坐标
- 用户匿名标识 `device_id` 在客户端生成，不关联可识别身份信息
- 支持 `opt_out` 机制：用户关闭追踪后，SDK停止所有上报
- GDPR/CCPA 合规：提供数据导出接口和用户删除请求处理流程
