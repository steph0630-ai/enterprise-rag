## 1. 系统概述

实时数据看板系统（Realtime Dashboard System, RDS）旨在为企业运营团队提供秒级数据刷新、多维度可视化的监控与分析平台。系统核心能力包括：

- 支持 1000+ 并发用户同时查看实时看板
- 数据延迟不超过 3 秒（P99）
- 支持 20+ 种数据源接入，包括 MySQL、Kafka、Elasticsearch、Prometheus
- 内置 50+ 预定义看板模板，支持用户自定义拖拽布局

## 2. 整体架构

系统采用 **微服务 + 事件驱动** 架构，分为四层：

```
+-----------------------------------------------------------+
|                      用户层 (Web/App)                       |
|   [React + TypeScript]  [WebSocket Client]                 |
+-----------------------------------------------------------+
|                    接入层 (API Gateway)                      |
|   [Kong Gateway]  [Rate Limiting]  [Auth]                  |
+-----------------------------------------------------------+
|                     业务服务层                               |
| +-------------------+  +-------------------+                |
| | Dashboard Service |  | Data Ingestion    |                |
| | (Go, gRPC)        |  | Service (Java)    |                |
| +-------------------+  +-------------------+                |
| +-------------------+  +-------------------+                |
| | Alert Service     |  | Template Service  |                |
| | (Python, Celery)  |  | (Node.js)         |                |
| +-------------------+  +-------------------+                |
+-----------------------------------------------------------+
|                     数据层                                   |
| [Redis Cluster] [Kafka] [PostgreSQL] [Elasticsearch]       |
+-----------------------------------------------------------+
```

## 3. 核心模块设计

### 3.1 数据接入服务

负责从多种数据源拉取原始数据，进行清洗、转换后推入 Kafka 消息队列。

**配置示例（`data-ingestion.yml`）：**

```yaml
service:
  name: data-ingestion-service
  port: 8081
  threads: 16

sources:
  - type: mysql
    host: 10.0.1.50
    port: 3306
    database: sales_db
    query: "SELECT id, amount, timestamp FROM orders WHERE timestamp > NOW() - INTERVAL 5 MINUTE"
    interval: 5s
  - type: kafka
    brokers:
      - 10.0.1.60:9092
      - 10.0.1.61:9092
      - 10.0.1.62:9092
    topics: [raw_events, user_actions]
    group_id: dashboard-ingestion-group
  - type: prometheus
    endpoint: http://10.0.1.70:9090
    metric: http_requests_total
    step: 10s

transform:
  - name: timestamp_normalize
    params:
      format: "YYYY-MM-DD HH:mm:ss"
  - name: metric_aggregate
    window: 10s
    function: sum
```

### 3.2 Dashboard Service

核心业务服务，负责看板定义管理、数据聚合查询、实时推送。

**关键接口：**

| 接口 | 方法 | 描述 | 响应时间上限 |
|------|------|------|-------------|
| `/api/v1/dashboards` | GET | 获取用户看板列表 | 100ms |
| `/api/v1/dashboards/{id}` | GET | 获取看板详情及数据 | 200ms |
| `/api/v1/dashboards/{id}/data` | GET | 刷新看板数据 | 500ms |
| `/ws/dashboard/{id}` | WebSocket | 实时推送数据更新 | 1s |

**WebSocket 连接池配置：**

```yaml
websocket:
  max_connections: 5000
  max_payload_size: 65536
  ping_interval: 30s
  pong_timeout: 10s
  write_buffer_size: 4096
  read_buffer_size: 4096
```

### 3.3 数据实时推送机制

采用 **WebSocket + Server-Sent Events (SSE)** 双通道方案：

1. **WebSocket 主通道**：用于低频更新（2~5秒），推送完整数据块
2. **SSE 辅助通道**：用于高频更新（0.5~1秒），推送增量变化

当用户数量超过 500 并发时，系统自动降级为仅使用 SSE 通道，以减少连接开销。

**客户端连接示例（JavaScript）：**

```javascript
// 主连接
const ws = new WebSocket('wss://dashboard.example.com/ws/dashboard/123');
ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
  updateChart(data);
};

// 辅助通道
const eventSource = new EventSource('https://dashboard.example.com/sse/dashboard/123');
eventSource.addEventListener('delta', (e) => {
  const delta = JSON.parse(e.data);
  applyDelta(delta);
});
```

## 4. 数据流与延迟

### 4.1 标准数据流

```
数据源 → 接入服务(0.5s) → Kafka(0.1s) → 流处理(0.2s) → Redis缓存(0.05s) → WebSocket推送(0.1s)
                                                                         ↓
                                                                    用户浏览器(0.05s)
```

**端到端延迟：** 约 1.0s（P50），2.5s（P99）

### 4.2 异常处理策略

| 异常场景 | 处理方式 | 降级措施 |
|---------|---------|---------|
| 数据源超时 | 重试3次，间隔1s | 显示最近一次缓存数据 |
| Kafka 集群故障 | 切换至备用集群 | 降级为静态看板 |
| Redis 连接失败 | 本地内存缓存 | 限制并发数至 200 |
| WebSocket 连接数超限 | 拒绝新连接 | 引导用户使用 SSE |

## 6. 部署与运维

**推荐部署方案：**

```
Kubernetes Cluster (6 Node)
├── 2 Node: API Gateway + Dashboard Service (Go)
├── 2 Node: Data Ingestion Service (Java) + Alert Service (Python)
├── 1 Node: Redis Cluster (3 Master + 3 Slave)
└── 1 Node: Kafka Broker (3 Brokers) + PostgreSQL + Elasticsearch
```

## 7. 安全与权限

1. **API 认证**：使用 JWT Token，有效期 2 小时，支持 Refresh Token
2. **看板权限**：支持三种级别——公开（无需认证）、团队（需团队Token）、私有（用户Token）
3. **数据脱敏**：敏感字段（如手机号、身份证）在推送前自动脱敏
4. **审计日志**：所有数据查询操作记录至 Elasticsearch，保留 90 天
