# 订单服务运维手册

## 服务概览

订单服务（order-service）负责处理所有订单相关的业务逻辑，包括创建订单、支付回调、订单状态流转等。

- **代码仓库**: git@github.com:company/order-service.git
- **部署环境**: K8s 集群 (prod-ns)
- **负责人**: 张三
- **Slack 频道**: #order-service

## 部署流程

### 1. 预发布验证

在部署到生产环境之前，必须先在 staging 环境完成以下验证：

```bash
kubectl exec -it deploy/order-service -n staging -- curl localhost:8080/health
```

### 2. 生产发布

```bash
kubectl apply -f k8s/production/deployment.yaml
kubectl rollout status deployment/order-service -n prod-ns --timeout=5m
```

### 3. 回滚步骤

如果发布后出现异常，执行：

```bash
kubectl rollout undo deployment/order-service -n prod-ns
kubectl rollout status deployment/order-service -n prod-ns
```

## 常见故障排查

### 问题1: 订单创建超时

**症状**: 用户下单后页面一直转圈，最终返回 504 Gateway Timeout

**排查步骤**:
1. 检查数据库连接池：`SELECT count(*) FROM pg_stat_activity WHERE state = 'active';`
2. 如果连接数超过 80，执行：`SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE state = 'idle' AND age(now(), state_change) > '10 min';`
3. 检查 Redis 连接：`redis-cli -h redis-master -p 6379 PING`

**已知原因**: 库存服务（inventory-service）的批量查询接口在并发超过 500 时会降级，导致订单服务线程池占满。

**解决方案**: 重启订单服务（临时），联系库存团队升级限流策略（永久）。

### 问题2: 支付回调丢失

**症状**: 用户已支付但订单状态仍为"待支付"

**排查步骤**:
1. 检查支付网关回调日志：`kubectl logs deploy/order-service -n prod-ns | grep "payment_callback" | tail -50`
2. 检查死信队列：RabbitMQ 管理界面 → Queues → `payment.dlq`
3. 手动触发补偿：`POST /api/internal/order/compensate/{order_id}`

## 配置修改方法

所有配置参数存储在 K8s ConfigMap 中，修改步骤：

```bash
# 1. 编辑 ConfigMap
kubectl edit configmap order-service-config -n prod-ns

# 2. 重启服务使配置生效
kubectl rollout restart deployment/order-service -n prod-ns

# 3. 验证配置已生效
kubectl exec -it deploy/order-service -n prod-ns -- cat /etc/config/app.yaml | grep ORDER_TIMEOUT
```

也可以在 Git 仓库中修改 `k8s/production/configmap.yaml` 后通过 CI/CD 自动部署。

## 配置参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| ORDER_TIMEOUT_SEC | 1800 | 未支付订单自动取消时间（秒） |
| MAX_ORDER_ITEMS | 50 | 单笔订单最大商品数 |
| PAYMENT_RETRY_COUNT | 3 | 支付回调失败重试次数 |
| DB_POOL_SIZE | 50 | 数据库连接池大小 |
