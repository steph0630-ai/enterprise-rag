## 2. 系统概述

用户权限管理系统（User Permission Management System, UPMS）负责企业内部所有应用系统的权限集中化管理。本系统基于 **RBAC 2.0（Role-Based Access Control）** 模型，结合**属性级权限控制（Attribute-Level Permission Control）**，支持细粒度的菜单权限、操作权限和数据权限管理。

### 2.1 核心目标

- 统一管理用户身份与角色分配
- 提供可继承的角色层级结构
- 支持按部门、项目、数据范围进行权限隔离
- 实现权限变更的实时同步与审计追踪

### 2.2 适用场景

- 企业ERP系统权限管理
- 内部OA审批流权限控制
- 数据分析平台的数据行级权限
- 多租户SaaS应用的租户隔离

## 3. 权限模型设计

### 3.1 核心实体关系

系统采用五层权限模型：

```
User → Role → PermissionGroup → Permission → Resource
```

| 实体 | 说明 | 示例 |
|------|------|------|
| User | 系统用户 | 张三 (uid=10086) |
| Role | 角色，可继承 | admin, editor, viewer |
| PermissionGroup | 权限分组 | 财务管理, 报表管理 |
| Permission | 原子权限点 | finance:invoice:create |
| Resource | 受控资源 | /api/v2/invoices |

### 3.2 角色继承规则

角色支持单继承，子角色自动继承父角色的所有权限。

```yaml
roles:
  - name: admin
    inherits_from: null
    permissions:
      - "*:*:*"
  - name: finance_manager
    inherits_from: editor
    permissions:
      - "finance:invoice:approve"
      - "finance:budget:write"
  - name: editor
    inherits_from: viewer
    permissions:
      - "finance:invoice:create"
      - "finance:invoice:edit"
  - name: viewer
    inherits_from: null
    permissions:
      - "finance:invoice:read"
      - "finance:report:read"
```

**注意**：当子角色与父角色存在相同权限点时，子角色定义优先。

### 3.3 数据权限维度

数据权限通过 **DataScope** 配置，支持以下维度：

| 维度 | 类型 | 描述 |
|------|------|------|
| org | 部门组织 | 按组织树层级控制数据可见性 |
| project | 项目 | 按项目组归属查看数据 |
| region | 区域 | 按地理区域（华北、华东等） |
| custom | 自定义 | 通过表达式引擎动态计算 |

示例数据权限配置：

```json
{
  "dataScope": {
    "type": "org",
    "rule": "department_id IN (SELECT sub_department_id FROM org_tree WHERE root_id = ?)",
    "param": 1001
  }
}
```

### 4.3 鉴权流程

1. 用户通过API Gateway发起请求，携带JWT Token
2. Auth Service验证Token有效性，解析用户ID和角色信息
3. Permission Service根据用户角色查询权限缓存（Redis）
4. 若缓存命中，直接校验权限；否则从PostgreSQL加载
5. 返回允许/拒绝结果，记录审计日志

**关键代码片段：**

```java
// 权限校验核心逻辑
public boolean checkPermission(String userId, String resource, String action) {
    // 1. 获取用户角色
    Set<String> roles = authService.getUserRoles(userId);
    
    // 2. 批量加载角色权限
    List<Permission> permissions = permissionCache.getPermissions(roles);
    
    // 3. 权限匹配
    for (Permission perm : permissions) {
        if (matchResource(perm.getResource(), resource) 
            && matchAction(perm.getAction(), action)) {
            return true;
        }
    }
    return false;
}
```

## 5. API接口设计

### 5.1 权限管理API

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 创建角色 | POST | /api/v2/roles | 新建角色并分配权限 |
| 更新角色 | PUT | /api/v2/roles/{roleId} | 修改角色权限集 |
| 删除角色 | DELETE | /api/v2/roles/{roleId} | 删除角色（需确认无用户绑定） |
| 分配角色 | POST | /api/v2/users/{userId}/roles | 为用户分配角色 |
| 查询用户权限 | GET | /api/v2/users/{userId}/permissions | 获取用户完整权限列表 |

### 5.2 请求/响应示例

**创建角色请求：**

```json
POST /api/v2/roles
{
  "roleName": "finance_analyst",
  "description": "财务分析师角色",
  "inheritsFrom": "viewer",
  "permissions": [
    "finance:invoice:create",
    "finance:report:write",
    "finance:budget:read"
  ],
  "dataScope": {
    "type": "org",
    "orgIds": [1001, 1002, 1005]
  }
}
```

**响应示例：**

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "roleId": 2048,
    "roleName": "finance_analyst",
    "createdAt": "2024-09-20T10:30:00+08:00"
  }
}
```

## 6. 数据库设计

### 6.1 核心表结构

**users 表：**

```sql
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    username VARCHAR(64) NOT NULL UNIQUE,
    password_hash VARCHAR(256) NOT NULL,
    email VARCHAR(128),
    department_id BIGINT REFERENCES departments(id),
    status SMALLINT DEFAULT 1,  -- 0:禁用, 1:启用
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_users_department ON users(department_id);
```

**role_permissions 表：**

```sql
CREATE TABLE role_permissions (
    id BIGSERIAL PRIMARY KEY,
    role_id BIGINT NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
    permission_id BIGINT NOT NULL REFERENCES permissions(id) ON DELETE CASCADE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(role_id, permission_id)
);

CREATE INDEX idx_role_permissions_role ON role_permissions(role_id);
```
