## 1. 概述

本规范定义公司所有后端服务（Java/Go/Python）的日志输出标准，包括日志级别划分、日志格式结构、敏感数据脱敏规则以及日志归档要求。所有新建项目必须遵循此规范；存量项目需在 2024Q4 前完成迁移。

---

## 2. 日志级别定义

日志级别从低到高依次为：TRACE < DEBUG < INFO < WARN < ERROR < FATAL。

### 2.1 级别说明

| 级别    | 使用场景                                                   | 示例                                      |
|---------|------------------------------------------------------------|-------------------------------------------|
| TRACE   | 仅用于开发环境或临时调试，生产环境禁止启用                   | SQL参数绑定明细                           |
| DEBUG   | 开发调试信息，默认关闭；可通过动态开关临时开启                | 请求入参、中间变量值、循环次数             |
| INFO    | 关键业务流程节点变更、正常状态切换                           | 用户注册成功、订单创建、定时任务完成       |
| WARN    | 预期内的异常或降级行为，不影响主流程                         | 限流触发、缓存未命中、重试第1次            |
| ERROR   | 功能不可用或数据不一致，需立即排查                           | 数据库连接失败、第三方接口超时、业务校验失败 |
| FATAL   | 系统完全不可用，导致进程退出或宕机                           | 无法加载核心配置、OOM错误                  |

### 2.2 生产环境默认级别

- 默认日志级别：INFO  
- 不允许将 ERROR 级别用于业务正常流程（如“用户被拒绝”应使用 WARN）  
- 单个服务每分钟 ERROR 日志超过 50 条时触发 P1 告警

## 3. 日志格式要求

所有日志统一以 **JSON 行格式**（one line per event）输出，字段使用驼峰命名，时间戳精确到毫秒。

### 3.1 通用字段

| 字段名          | 类型   | 是否必须 | 说明                                            |
|-----------------|--------|----------|-------------------------------------------------|
| timestamp       | string | 是       | ISO 8601 格式，含时区，示例：2024-07-15T14:30:00.123+08:00 |
| level           | string | 是       | 大写日志级别                                    |
| loggerName      | string | 是       | 记录日志的类名或模块名                          |
| threadName      | string | 是       | 当前线程名                                      |
| message         | string | 是       | 日志内容，禁止包含敏感数据                      |
| traceId         | string | 条件     | 分布式链路追踪 ID（若有）                       |
| spanId          | string | 条件     | 当前 Span ID                                    |
| appName         | string | 是       | 服务名称，例如 `order-service`                  |
| hostName        | string | 是       | 主机名或 Pod 名称                               |
| mdcFields       | object | 否       | 自定义 MDC 上下文，如 `{"userId":"123456"}`    |

### 3.2 异常日志专用字段

当 level 为 ERROR 或 FATAL 时，必须额外包含：

| 字段名      | 类型   | 说明                              |
|-------------|--------|-----------------------------------|
| exception   | string | 异常类型，如 `java.lang.NullPointerException` |
| stackTrace  | string | 异常堆栈信息（单行，用 `\n` 替换换行）        |

### 3.3 日志输出示例

```json
{
  "timestamp": "2024-07-15T14:30:00.123+08:00",
  "level": "ERROR",
  "loggerName": "com.example.order.service.OrderService",
  "threadName": "http-nio-8080-exec-5",
  "message": "订单创建失败：库存不足",
  "traceId": "abc123def456",
  "spanId": "span-001",
  "appName": "order-service",
  "hostName": "pod-2a3b4c5d",
  "mdcFields": {
    "userId": "user_98765",
    "orderId": "ORD-20240715-0001"
  },
  "exception": "com.example.exception.InsufficientStockException",
  "stackTrace": "com.example.order.service.OrderService.createOrder(OrderService.java:85)\nat com.example.order.controller.OrderController.create(OrderController.java:42)\n..."
}
```

## 4. 脱敏规则

所有日志输出前必须经过脱敏处理，严禁明文输出以下敏感字段。

### 4.1 需脱敏字段列表

| 字段类别       | 字段名示例        | 脱敏规则                                                   | 脱敏后示例               |
|----------------|-------------------|------------------------------------------------------------|--------------------------|
| 用户手机号     | phone, mobile     | 保留前3位和后4位，中间用 `****` 代替                       | `138****5678`            |
| 邮箱地址       | email             | 保留 @ 前第一个字符和 @ 后域名，其余用 `*` 代替            | `a***@example.com`       |
| 身份证号       | idCard            | 保留前6位和后4位，中间用 `********` 代替                   | `110101********1234`     |
| 银行卡号       | bankCard, cardNo  | 保留前4位和后4位，中间用 `**** ****` 代替                 | `6222 **** **** 5678`    |
| 密码/令牌      | password, secret  | 完全替换为 `******`                                        | `******`                 |
| 真实姓名       | realName, name    | 保留姓氏，名用 `*` 代替                                    | `张*`                    |

### 4.2 脱敏实现要求

- 推荐使用 AOP 或 Logback 的 `MessageConverter` 进行统一脱敏，禁止在业务代码中手动拼接脱敏字符串  
- 对于自定义对象，必须实现 `@Sensitive` 注解或注册脱敏策略  
- 审计日志（涉及用户操作）必须脱敏后输出，原始数据可保留在数据库但需加密存储

### 4.3 脱敏示例（Java Logback 配置片段）

```xml
<!-- logback-spring.xml 中配置脱敏转换器 -->
<conversionRule conversionWord="maskedMsg"
                converterClass="com.example.logging.SensitiveDataConverter" />

<appender name="JSON_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
    <encoder class="ch.qos.logback.classic.encoder.JsonEncoder">
        <pattern>
            %maskedMsg
        </pattern>
    </encoder>
</appender>
```

## 5. 日志归档与保留策略

| 日志级别 | 保留时长 | 存储位置          | 备注                            |
|----------|----------|-------------------|---------------------------------|
| INFO     | 30天     | `/var/log/{app}/` | 按天滚动，保留最近30天           |
| WARN     | 30天     | 同上              | 同上                            |
| ERROR    | 90天     | 同上              | 单独文件 `error.log`，保留90天  |
| FATAL    | 180天     | 同上              | 单独文件 `fatal.log`，保留180天 |

- 归档文件命名格式：`{appName}.{yyyy-MM-dd}.{level}.log`
- 日志文件大小上限：单个文件最大 500MB，超出后自动滚动到 `.1`、`.2` 等后缀
- 所有日志必须同步写入集中式日志平台（ELK / Loki），生产环境禁止使用 `System.out.println()`

---

## 6. 合规与检查

- 每季度由 CI/CD 流水线执行日志格式检查，不符合规范的 PR 将被阻止合并  
- 安全团队每月扫描日志文件，发现明文敏感数据立即通知整改，记录为安全事件  
- 审计日志（如用户登录、权限变更）必须保留至少 1 年，不可删除
