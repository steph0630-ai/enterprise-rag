## 2. 目的与范围

本制度旨在建立公司技术文档（包括但不限于：产品文档、API文档、系统架构文档、运维手册、SDK接入指南等）的编写、审核、发布、维护与废弃的全生命周期管理规范，确保文档的准确性、完整性、一致性和时效性。

**适用范围：** 研发中心、测试中心、运维中心、产品中心所有涉及技术文档产出与维护的团队。

## 3. 角色与职责

| 角色 | 职责说明 | 对应人员 |
|------|----------|----------|
| 文档编写人 | 负责文档的初始编写与持续更新 | 各技术岗位成员 |
| 技术审核人 | 审核内容准确性、技术可行性 | 对应模块技术负责人 |
| 质量审核人 | 审核格式规范、术语统一、可读性 | 技术文档组专职人员 |

| 发布管理员 | 执行文档发布流程，管理权限与版本 | 技术文档组 |

> **责任矩阵：** 每个技术项目必须在立项阶段指定一名**文档负责人**，该负责人需在项目甘特图中标注文档交付里程碑。

## 4. 文档编写规范

### 4.1 通用格式要求

所有技术文档需使用 Markdown 格式编写，并使用公司统一的模板（模板路径：`gitlab.com/doc-templates/standard-template.md`）。基本结构必须包含：

```
# 文档标题
## 概述
## 环境要求
## 安装/配置步骤
## 使用说明
## 常见问题
## 变更记录
```

### 4.2 代码块与配置示例

- 所有命令行、配置文件片段、API请求/响应必须使用代码块包裹，并标注语言类型。
- 示例必须基于真实环境编写，禁止使用`example.com`、`your-password`等占位符（需替换为`<your-domain>`、`<your-token>`等带尖括号的变量标记）。

**正确示例：**

```bash
# 部署前端应用
cd /opt/app/web
npm install --production
nohup node server.js --port 8080 > /var/log/app.log 2>&1 &
```

**正确示例：**

```yaml
# docker-compose.yml 核心配置片段
services:
  redis:
    image: redis:7.2-alpine
    ports:
      - "6379:6379"
    volumes:
      - ./data/redis:/data
```

### 4.3 表格与列表

- 使用表格对比不同方案、不同版本的差异。
- 有序列表用于步骤说明，无序列表用于特性列举。

**示例：数据库选型对比**

| 数据库 | 版本 | 适用场景 | 推荐配置 |

| PostgreSQL | 16.2 | OLTP、地理空间数据 | 4核8G起步 |
| ClickHouse | 24.1 | OLAP、日志分析 | 8核16G起步 |
| Redis | 7.2 | 缓存、会话管理 | 2核4G起步 |

## 5. 审核与发布流程

### 5.1 审核链条

每份文档必须经过以下审核阶段方可发布：

1. **技术审核**（24小时内完成）
   - 审核人检查技术细节是否准确，命令行参数是否正确，API响应字段是否与代码一致。
2. **质量审核**（48小时内完成）
   - 审核人检查拼写错误、格式一致性、术语统一性（参照公司术语表`terminology.yml`）。
3. **发布审批**（由文档负责人在GitLab发起MR，指定发布管理员合并）

### 5.2 自动化检测工具

所有文档提交前，必须通过以下自动化检查：

```bash
# 在本地运行文档质量检测脚本
./scripts/check-docs.sh --path docs/api/v3
```

该脚本会执行：
- Markdown语法校验（markdownlint）
- 术语一致性检查（基于术语表）
- 链接有效性检查（检测内部交叉引用与外部URL）
- 代码块语法高亮验证

## 6. 维护与废弃机制

### 6.1 文档生命周期

- **活跃文档：** 每季度至少更新一次，由文档负责人负责。
- **归档文档：** 若模块或功能被弃用，文档负责人需在标题添加`[已废弃]`标记，并注释替代文档的链接。
- **删除文档：** 仅发布管理员有权删除，删除前需在文档组群内公告，保留30天缓冲期。

### 6.2 过期文档检测

每月初，技术文档组通过CI/CD流水线自动扫描所有文档：

```python
# 伪代码示例：检测文档最后修改时间
def check_doc_expiry():
    for doc in get_all_docs():
        last_modified = doc.git_last_commit_time
        if (now - last_modified).days > 90:
            notify(doc.owner, f"文档 {doc.path} 已超过90天未更新")
```
