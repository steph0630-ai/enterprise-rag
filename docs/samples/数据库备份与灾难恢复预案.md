## 1. 概述

本预案定义了公司核心数据库（MySQL 8.0、PostgreSQL 15、Redis 7.2）的备份策略、灾难恢复流程以及定期演练要求。目标是在发生硬件故障、数据损坏或人为误操作时，能够在规定时间内恢复业务数据。

**关键指标：**
- **RPO (Recovery Point Objective):** 15分钟（MySQL/PostgreSQL），1分钟（Redis）
- **RTO (Recovery Time Objective):** 30分钟（全库恢复），5分钟（单表/单Key恢复）

## 2. 备份策略

### 2.1 备份类型与周期

| 数据库类型 | 备份类型 | 周期 | 保留策略 | 存储位置 |
|-----------|---------|------|---------|---------|
| MySQL 8.0 | 全量备份 (Xtrabackup) | 每日 02:00 | 保留7天 | 本地SSD `/data/backup/mysql/full/` |
| MySQL 8.0 | 增量备份 (binlog) | 每10分钟 | 保留72小时 | 本地SSD `/data/backup/mysql/binlog/` |
| PostgreSQL 15 | 全量备份 (pg_basebackup) | 每日 03:00 | 保留14天 | 本地SSD `/data/backup/pg/full/` |
| PostgreSQL 15 | WAL归档 | 连续 | 保留48小时 | 本地SSD `/data/backup/pg/wal/` |
| Redis 7.2 | RDB快照 | 每60分钟 | 保留24小时 | 本地 `dump.rdb` |
| Redis 7.2 | AOF日志 | 每秒fsync | 保留7天 | 本地 `appendonly.aof` |
| **所有类型** | **异地备份** | 每日 04:30 | 保留30天 | 腾讯云COS `backup-prod-2024/db/` |

### 2.2 备份脚本示例 (MySQL)

以下为生产环境 MySQL 全量备份脚本，位于 `/usr/local/bin/mysql_backup.sh`。

```bash
#!/bin/bash
# MySQL Full Backup using Percona XtraBackup
# Author: DBA Team
# Version: 2.3

BACKUP_DIR="/data/backup/mysql/full"
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_PATH="${BACKUP_DIR}/${DATE}"
MYSQL_USER="backup_user"
MYSQL_PASS="$(cat /etc/mysql/backup.pass)"
MYSQL_HOST="127.0.0.1"
MYSQL_PORT=3306
REMOTE_PATH="cos://backup-prod-2024/db/mysql/"

# 创建备份目录
mkdir -p "${BACKUP_PATH}"

# 执行全量备份
xtrabackup --backup \
    --user="${MYSQL_USER}" \
    --password="${MYSQL_PASS}" \
    --host="${MYSQL_HOST}" \
    --port=${MYSQL_PORT} \
    --target-dir="${BACKUP_PATH}" \
    --parallel=4 \
    --compress \
    --compress-threads=2

# 检查备份状态
if [ $? -eq 0 ]; then
    echo "[INFO] Backup completed successfully: ${BACKUP_PATH}"
    
    # 应用日志 (prepare)
    xtrabackup --prepare --target-dir="${BACKUP_PATH}" --apply-log-only
    
    # 上传到COS
    /usr/local/bin/coscli cp -r "${BACKUP_PATH}" "${REMOTE_PATH}${DATE}/" --recursive
    
    # 清理本地超过7天的备份
    find "${BACKUP_DIR}" -type d -mtime +7 -exec rm -rf {} \;
else
    echo "[ERROR] Backup failed!"
    /usr/local/bin/alert-sender --channel slack --message "MySQL backup failed at ${DATE}"
    exit 1
fi
```

### 2.3 Redis RDB 快照配置

在 `/etc/redis/redis.conf` 中配置：

```conf
# 每60分钟至少1个key变更则触发RDB
save 3600 1
# 每300分钟至少100个key变更
save 300 100
# 每60秒至少10000个key变更
save 60 10000

# RDB文件压缩
rdbcompression yes
# RDB文件校验和
rdbchecksum yes

# AOF配置
appendonly yes
appendfsync everysec
auto-aof-rewrite-percentage 100
auto-aof-rewrite-min-size 64mb
```

## 3. 灾难恢复流程

### 3.1 故障分级响应

| 级别 | 描述 | 响应时间 | 负责人 |
|------|------|---------|--------|
| P0 | 核心库完全不可用，影响线上交易 | 立即响应 | DBA + Infra On-Call |
| P1 | 部分表损坏，影响报表或非核心业务 | 15分钟内 | DBA值班 |
| P2 | 单行数据误删，可通过binlog恢复 | 30分钟内 | DBA按需处理 |

### 3.2 MySQL 全量恢复步骤

**场景：** 生产数据库实例 `db-prod-01` 磁盘损坏，需要从最新备份恢复。

1. **停止应用访问**
   ```bash
   systemctl stop app-proxy
   ```

2. **准备备份文件**
   ```bash
   # 从COS下载最新备份
   COS_MYSQL_PATH="cos://backup-prod-2024/db/mysql/$(date +%Y%m%d)_*"
   /usr/local/bin/coscli cp -r "${COS_MYSQL_PATH}" /tmp/restore/
   
   # 解压缩备份
   cd /tmp/restore
   xtrabackup --decompress --target-dir=./ --parallel=4
   ```

3. **执行恢复**
   ```bash
   # 应用redo log
   xtrabackup --prepare --target-dir=./ --apply-log-only
   
   # 停止MySQL服务
   systemctl stop mysql
   
   # 复制数据文件
   xtrabackup --copy-back --target-dir=./ --datadir=/var/lib/mysql/
   
   # 修复权限
   chown -R mysql:mysql /var/lib/mysql/
   
   # 启动MySQL
   systemctl start mysql
   ```

4. **应用binlog追赶到故障点**
   ```bash
   mysqlbinlog --start-datetime="2024-12-10 02:00:00" \
       --stop-datetime="2024-12-10 03:35:00" \
       /data/backup/mysql/binlog/mysql-bin.000012 | mysql -u root -p
   ```

5. **验证数据完整性**
   ```sql
   SELECT COUNT(*) FROM orders WHERE create_date >= '2024-12-10';
   ```

6. **恢复应用访问**
   ```bash
   systemctl start app-proxy
   ```

### 3.3 Redis 快速恢复

**场景：** Redis 节点 `redis-01` 宕机，从AOF日志恢复。

```bash
# 1. 停止Redis
redis-cli -h 127.0.0.1 -p 6379 SHUTDOWN

# 2. 检查AOF文件完整性
redis-check-aof /var/lib/redis/appendonly.aof

# 3. 修复AOF（如有问题）
redis-check-aof --fix /var/lib/redis/appendonly.aof

# 4. 启动Redis，自动加载AOF
systemctl start redis

# 5. 验证数据
redis-cli DBSIZE
redis-cli INFO keyspace
```
