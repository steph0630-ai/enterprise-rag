## 1. 领域概述

商品库存管理系统（Inventory Management System, IMS）服务于电商平台的核心库存管理需求，支持多仓库、多SKU、批次追踪、库存锁定与释放、出入库流水记录等业务场景。本设计遵循领域驱动设计（DDD）原则，将库存核心逻辑与外部依赖（如订单系统、采购系统）解耦，确保库存数据的一致性、实时性和可追溯性。

---

## 2. 核心领域对象

### 2.1 实体（Entity）

| 实体名称          | 标识属性   | 简要描述                                         |
|-------------------|------------|--------------------------------------------------|
| Sku               | skuId      | 商品SKU，唯一标识一种具体商品（如颜色、尺寸组合） |
| Warehouse         | warehouseId| 仓库实例，包含地理位置、容量等属性               |
| InventoryItem     | itemId     | SKU在特定仓库的库存记录，包含可用量、锁定量等     |
| InventoryBatch    | batchId    | 同一SKU入库的批次，记录生产日期、过期时间、成本   |
| InventoryLock     | lockId     | 库存锁定记录，关联订单或出库单，包含锁定数量      |
| InventoryTransaction | txnId   | 库存变动流水，记录每一次增减的动作                |

### 2.2 值对象（Value Object）

- **Quantity**：包含 `available`（可用量）、`locked`（锁定量）、`total`（总库存量）三元组，支持加减运算和校验。
- **ShelfLife**：包含 `productionDate`（生产日期）、`expireDate`（过期日期），用于批次过期预警。
- **Location**：仓库内具体货架或库位坐标，格式为 `{zone}:{aisle}:{shelf}:{bin}`，如 `A:01:02:03`。

### 2.3 聚合（Aggregate）

**InventoryItem** 是库存管理的核心聚合根，包含以下内部逻辑：

- 修改可用量时自动校验不得低于零
- 锁定库存时创建 `InventoryLock` 并更新 `locked` 量
- 释放锁定时删除 `InventoryLock` 并回滚 `locked` 量
- 生成 `InventoryTransaction` 记录每一次变更

聚合边界：InventoryItem 直接管理自己的批次列表（`List<InventoryBatch>`）和锁定列表（`List<InventoryLock>`）。外部系统通过 `SkuId + WarehouseId` 获取聚合根。

## 3. 领域服务

### 3.1 库存预留服务（InventoryReservationService）

负责从指定仓库的SKU中预留库存，支持“先进先出”（FIFO）策略选择批次。

**接口定义（伪代码）：**

```java
public interface InventoryReservationService {
    /**
     * 预留库存
     * @param skuId      商品SKU
     * @param warehouseId 仓库ID
     * @param quantity   预留数量
     * @param orderId    关联订单ID
     * @return 预留是否成功
     */
    boolean reserveStock(String skuId, String warehouseId, Quantity quantity, String orderId);
}
```

**FIFO批次选择逻辑（简化）：**

```sql
-- 查询该SKU在该仓库中可用量>0、且未过期的批次，按生产日期升序排列
SELECT batch_id, available_quantity 
FROM inventory_batch 
WHERE sku_id = ? AND warehouse_id = ? AND available_quantity > 0 AND expire_date > NOW()
ORDER BY production_date ASC;
```

### 3.2 库存释放服务（InventoryReleaseService）

当订单取消或退款时调用，释放已锁定的库存。释放时优先释放最近锁定批次。

### 3.3 库存同步服务（InventorySyncService）

定期将数据库中的库存快照同步到缓存（Redis）和搜索引擎（Elasticsearch），用于前台实时展示。

**配置示例（application.yml）：**

```yaml
inventory:
  sync:
    enabled: true
    cron: "0 */5 * * * ?"   # 每5分钟同步一次
    batch-size: 1000
    cache:
      type: redis
      ttl-seconds: 300
```

## 4. 仓储层设计

仓储（Repository）负责持久化聚合根，并提供按标识查询的能力。主要接口如下：

```java
public interface InventoryItemRepository {
    InventoryItem findBySkuAndWarehouse(String skuId, String warehouseId);
    
    void save(InventoryItem item);
    
    List<InventoryItem> findBySkuId(String skuId);
    
    // 乐观锁版本号更新
    boolean updateWithVersion(InventoryItem item, int expectedVersion);
}
```

数据库表设计核心部分（MySQL）：

```sql
CREATE TABLE `inventory_item` (
  `id` BIGINT NOT NULL AUTO_INCREMENT,
  `sku_id` VARCHAR(64) NOT NULL,
  `warehouse_id` VARCHAR(32) NOT NULL,
  `total_quantity` INT NOT NULL DEFAULT 0,
  `locked_quantity` INT NOT NULL DEFAULT 0,
  `available_quantity` INT GENERATED ALWAYS AS (total_quantity - locked_quantity) STORED,
  `version` INT NOT NULL DEFAULT 0,
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_sku_warehouse` (`sku_id`, `warehouse_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE `inventory_batch` (
  `batch_id` VARCHAR(64) NOT NULL,
  `sku_id` VARCHAR(64) NOT NULL,
  `warehouse_id` VARCHAR(32) NOT NULL,
  `available_quantity` INT NOT NULL,
  `production_date` DATE NOT NULL,
  `expire_date` DATE DEFAULT NULL,
  `cost_price` DECIMAL(10,2) NOT NULL,
  `location` VARCHAR(64) DEFAULT NULL,
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`batch_id`),
  INDEX `idx_sku_warehouse` (`sku_id`, `warehouse_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 5. 领域事件（Domain Events）

库存变动时发布以下事件，供其他微服务订阅：

| 事件名称                 | 包含字段                                         | 触发时机               |
|--------------------------|--------------------------------------------------|------------------------|
| StockReservedEvent       | skuId, warehouseId, quantity, orderId, timestamp | 库存预留成功           |
| StockReleasedEvent       | skuId, warehouseId, quantity, orderId, timestamp | 库存释放成功           |
| StockOutOfStockEvent     | skuId, warehouseId, remainingQuantity, timestamp | 可用量降为0            |
| BatchExpiredEvent        | batchId, skuId, expireDate, timestamp            | 批次过期预警（提前N天） |

事件通过消息队列（如 RabbitMQ 或 Kafka）异步广播，保证最终一致性。

## 6. 关键约束与规则

1. **库存不可为负**：任何修改库存的操作必须校验 `available_quantity >= 0`，否则抛出 `InsufficientStockException`。
2. **乐观锁并发控制**：`inventory_item` 表使用 `version` 字段实现乐观锁，防止并发扣减导致超卖。
3. **锁定量上限**：`locked_quantity` 不得超过 `total_quantity`，锁定操作需先校验可用量。
4. **批次过期处理**：系统每日定时任务扫描过期批次，将其可用量置零并发布 `BatchExpiredEvent`。

## 7. 附录：典型业务流程示例

### 7.1 下单扣减库存流程

```
用户下单 -> 订单服务调用 InventoryReservationService.reserveStock()
  -> 查找 InventoryItem（skuId+warehouseId）
  -> 校验可用量 >= 预留数量
  -> 按FIFO选择批次，更新批次可用量
  -> 创建 InventoryLock 记录
  -> 更新 InventoryItem.locked_quantity
  -> 生成 InventoryTransaction（类型=RESERVE）
  -> 发布 StockReservedEvent
```
